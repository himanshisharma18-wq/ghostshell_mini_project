# GhostShell Delivery Checklist

## Original delivery outcomes

- [x] **Explain shell commands safely.** Explain pasted shell commands in beginner-friendly language, including their purpose, syntax, typical usage, and potential risks, without ever executing them. The API request path, untrusted-input instruction, safety prompt, and no-execution code path are implemented and covered at the Ollama request boundary.
- [x] **Analyze programming errors and tracebacks.** Identify likely causes in pasted errors/logs/tracebacks and suggest clear step-by-step fixes and reviewable commands. The error-analysis mode sends the pasted content to the configured local model with beginner-friendly fix instructions.
- [x] **Keep the assistant beginner-friendly and on-brand.** Provide a subtle ghost-themed personality while keeping technical explanations accurate, professional, readable, and accessible to beginners. The system instructions set this tone and constrain the ghost narration.
- [ ] **Use functional local AI inference.** Connect Flask to Ollama and a locally running open-weight model; support configurable model selection, hardware guidance, and clear handling when Ollama or the model is unavailable. The application uses the real Ollama `/api/chat` HTTP endpoint and validates selected tags against the actual local `/api/tags` list. Request construction and unavailable-service handling are tested, but an actual response from a downloaded model has not been verified because Ollama and model weights are not installed in this build sandbox.
- [x] **Implement resilient frontend-to-model request flow.** Complete vanilla JavaScript frontend → Flask → Ollama → Flask → displayed response flow with input validation, structured API errors, loading states, and failure handling. Flask routes and API boundaries are covered by tests; the page, CSS, JavaScript, and route manifest were checked over HTTP.
- [x] **Deliver the responsive terminal interface.** Include a dark terminal-style interface with green typography, tasteful ghost animations, example prompts, current-session chat history, and a polished developer-tool aesthetic. Responsive styles, reduced-motion handling, ghost animation, examples, and session controls are implemented; desktop and mobile layouts were visually inspected.
- [x] **Enforce safety and privacy.** Treat all input as untrusted, never automatically run commands, warn about risky actions, avoid secret exposure, and keep inference local by default. The app has no execution endpoint; the prompt treats user text as data, common credential formats receive best-effort masking, responses are rendered as text, and the UI/README warn users to review commands and remove secrets themselves. The health API and UI distinguish a syntactically loopback Ollama host from a custom host.
- [ ] **Document Windows and offline use.** Support local Windows setup with exact PowerShell commands and document offline use after installation/model download, including an offline test procedure. README includes Windows commands and an offline test procedure, but neither Windows execution nor the offline procedure has been manually verified in this sandbox.
- [x] **Include source, repository files, and tests.** Organize source folders; include `requirements.txt`, `.gitignore`, configuration examples only if needed, and tests for major frontend/backend integration points without claiming untested features work. Source folders, dependencies, ignore rules, MIT source license, route manifest, and 13 standard-library tests are present; no `.env.example` is needed because the app requires no credentials or `.env` loader.
- [x] **Write complete contributor documentation.** README covers prerequisites, file-by-file explanations, architecture, model choice/licensing and hardware, troubleshooting, privacy, sample inputs, testing, GitHub guidance, and how local open-weight AI differs from a closed hosted API and satisfies the challenge. README links official Ollama, Qwen, and Windows references, gives exact PowerShell commands, and distinguishes verified boundary tests from unverified live inference.

## Expanded workbench outcomes

- [x] **Add additional useful AI workflows.** Besides command explanation and error analysis, let users explore a code-understanding mode and a safety/risk-review mode with beginner-friendly outputs; explain likely causes and risks without making guarantees or claiming formal security certification. Flask supports all four modes, and tests verify distinct code and safety prompt paths.
- [x] **Let users select installed local models.** Show the model tags actually available from the configured local Ollama instance, allow selection for an analysis request, and return clear errors when Ollama or a chosen model is missing. Do not add hosted model names or silently pull models. The model shelf and selector use `/api/tags`; Flask allowlists the selected installed tag and tests cover installed, missing, and invalid selections.
- [x] **Make feature discovery useful.** Add explorable quick-start/tool cards and a recent-prompt/session-history area that lets a user revisit or edit prompts in the current browser session; do not claim that preferences or history are learned or persist on a server. Four tool cards, examples, five in-memory recent prompts, and a clear-session action are implemented; desktop and mobile dashboard layouts were inspected.
- [x] **Keep the terminal experience review-only.** Add useful terminal/code-workbench panels inspired by the supplied dashboard reference, but never add an auto-executing command runner. All candidate commands stay visible as text for the user to review. The visual session console explicitly has no shell attached, and the backend has no command-execution path.
